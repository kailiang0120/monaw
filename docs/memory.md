# Memory

Monaw remembers things in two scopes:

| Scope | Holds | Used in |
| --- | --- | --- |
| Global | Things about you that apply everywhere: how you want replies written, rules for how Monaw should work, facts about you. | Every conversation. |
| Workspace | Things that belong to one working folder: its conventions, commands, architecture decisions. | Only conversations in that folder. |

Each memory also has a kind:

| Kind | Meaning | When it reaches the prompt |
| --- | --- | --- |
| `rule` | How Monaw must behave ("Ask before changing public APIs."). | Every turn. |
| `preference` | Likes and dislikes ("Prefers pnpm over npm."). | Every turn. |
| `fact` | Anything else worth knowing ("Invoices are generated by the nightly cron job."). | Only when it matches your message. |

Chat history stays in SQLite. Memory is plain markdown, and there is no memory data in the database.

## Turning It On or Off

Settings -> Identity has a **Memory** switch. When it is off, nothing is read from or written to memory. The `memory` section of the runtime `settings.json` file has a few advanced values:

| Setting | Default | Meaning |
| --- | --- | --- |
| `enabled` | `true` | The Memory switch. |
| `auto_learn` | `true` | Learn from your messages in the background (see below). Explicit "remember this" requests work either way. |
| `retrieval_limit` | `6` | Most facts added to one turn. |
| `max_injected_chars` | `2500` | Character budget for the memory block in the prompt. |
| `min_relevance_score` | `0.15` | Share of your message's distinctive words a fact must cover before it is used. |

## Where It Is Stored

```text
%USERPROFILE%\.monaw\memory\
  global.md                        global memory
  workspaces\<folder>-<hash>.md    one file per workspace folder
  legacy-v1\                       the pre-v2 memory layout, moved aside on first start
```

Set `AGENT_MEMORY_DIR` to use a different folder, or move all Monaw data with `MONAW_HOME` or `AGENT_HOME`. A conversation without a chosen folder uses Monaw's default workspace, which has its own workspace memory like any other folder.

## File Format

```markdown
---
schema: monaw-memory-v2
scope: workspace
workspace: C:\Users\you\code\billing
updated_at: '2026-10-18T10:00:00+00:00'
---

# Workspace memory: billing

## Rules

- Use pnpm, never npm, in this repo. <!-- id:m-3f9a2c1d i:7 s:user c:2026-10-18T10:00:00+00:00 u:2026-10-18T10:00:00+00:00 -->

## Preferences

## Facts

- Invoices are generated by the nightly cron job. <!-- id:m-8b21e0aa i:5 s:learned c:... u:... -->
```

Edit the files in any text editor. Put one memory per bullet under `## Rules`, `## Preferences`, or `## Facts`; a bullet under any other heading counts as a fact. A bullet without the trailing comment is fine: Monaw gives it an id and writes the comment back the next time it saves the file. In the comment, `i` is importance (1 to 10, higher comes first), `s` is where the memory came from (`user`, `learned`, or `manual`), and `c`/`u` are the created and updated times.

## How Memory Is Used

At the start of each turn Monaw adds a `## Memory` block to the system prompt:

1. **About the user**: global rules and preferences.
2. **This workspace**: the current folder's rules and preferences.
3. **Relevant notes**: facts from both scopes that match your message.

Rules and preferences are listed by importance, newest first, and take up to 60% of the budget. Any that do not fit compete with facts on relevance. Matching ignores function words and memory boilerplate ("The user prefers…"), and words that are rare across your memories count more than common ones. Short follow-ups such as "yes, do it" also use your previous two messages. Memories never override system instructions, safety policy, tool contracts, approvals, or filesystem permissions.

## How Memory Is Written

Memory only ever comes from your own words.

| Path | Trigger | Safeguard |
| --- | --- | --- |
| `memory_remember`, `memory_update` | You ask Monaw to remember or correct something. The agent picks the scope and kind. | The content must mostly use words from your message in this turn, so text from a web page or file cannot be saved. Interactive sessions only. |
| `memory_forget` | You ask Monaw to forget something. | Interactive sessions only. |
| Background learning | After an interactive turn whose messages (including any you sent mid-turn) sound durable ("from now on…", "I prefer…", "we use…", "remember…"). It runs after the reply, so it never delays the turn. Scheduled tasks and Telegram runs are skipped, as they are for the tools. | The model sees only your messages and your existing memories, never assistant replies or tool output. Each addition or correction must be grounded in your words, and deletions can only target existing ids. |

Every write is also checked for secrets (API keys, tokens such as `ghp_…`, `AKIA…`, `xoxb-…`, JWTs, private keys, passwords, card and ID numbers) and length (8 to 500 characters). Saving something close to an existing memory in the same scope refreshes that memory instead of adding a near-copy.

## API Surface

All endpoints are under `/api`. `workspace` is a folder path; empty means the default workspace. Global memories are always included alongside the workspace's own.

| Endpoint | Purpose |
| --- | --- |
| `GET /api/memories?workspace=&scope=` | List memories. |
| `GET /api/memories/search?query=&workspace=&scope=&limit=` | Rank memories against a query, with `score` and `relevance`. |
| `GET /api/memories/workspaces` | List workspaces that have a memory file. |
| `POST /api/memories` | Create a memory: `content`, `scope`, `kind`, `importance`, `workspace`. |
| `PATCH /api/memories/{id}?workspace=` | Change `content`, `kind`, or `importance`. |
| `DELETE /api/memories/{id}?workspace=` | Delete a memory. |

## Troubleshooting

| Symptom | Check |
| --- | --- |
| No memories are being used. | Confirm the Memory switch under Settings -> Identity is on and look in `%USERPROFILE%\.monaw\memory` (or `AGENT_MEMORY_DIR`). |
| A rule is missing from the prompt. | It must be under `## Rules` or `## Preferences` in `global.md` or the current folder's workspace file. Lower-importance rules drop out when the budget is full. |
| A fact is not used. | It only appears when your message shares distinctive words with it; try `GET /api/memories/search`. |
| "Remember this" is refused. | The agent paraphrased too far from what you said (`memory_not_user_stated`), or the content looks like a secret. |
| A hand-edited bullet disappeared. | It was shorter than 8 characters, or it was a duplicate of another bullet in the same file. |
| Old memories are gone. | The pre-v2 files were moved to `legacy-v1\` in the memory folder; nothing was deleted. |
