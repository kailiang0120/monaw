2026-11-04 · Windows 11 x64 · tested source commit `9e04893` · version `1.1.0`

All automated application and backend scenarios used a disposable Monaw home,
temporary workspace, and a fake model provider. The local installer is a
candidate, not a published release.

The crash matrix kills a real worker process before and after operation intent,
halfway through a file write, after the file write but before verification is
committed, after verification but before returning the tool result, and after
the tool outcome but before the message checkpoint. Recovery is read-only and
never repeated the write. A partial write remains uncertain and needs review.

The Electron suite checked file Diff before approval, a verified write, safe
Pause, replacement of both Electron and backend processes, recovery and
Continue on a new attempt, and Undo. It also checked an external-edit conflict,
SSE reconnect, keyboard controls, repeated clicks, and a separate hard backend
crash/restart without repeating a completed file operation. The hard-crash path
has not yet been combined with Continue in the same Electron scenario.

## Release gates still open

- Run the installed upgrade from the published v1.0.0 installer to the v1.1.0
  candidate on a clean Windows machine using the Upgrade check workflow. The
  local database migration and unpacked restart checks do not replace it.
- Run the opt-in packaged ChatGPT sign-in and model-driven tool check with an
  authorized account. No live provider account was used during this run.
- Finish an end-to-end Electron case that combines an abrupt backend crash,
  startup recovery and Continue for the same Run. Existing tests separately
  cover hard-crash recovery and Continue after a safely paused restart.

Undo requires current stable permissions that do not require confirmation or
an access grant. There is currently no second approval flow for Undo, so the
default confirmation policy can make it unavailable. The Electron Undo tests
explicitly enable full access in their disposable fixture after approving the
original file write. Run events have no automatic age-based cleanup; deleting a
conversation cascades database rows but does not immediately erase snapshot
files. See [operations.md](operations.md) and [permissions.md](permissions.md).
