# Browser action reliability and recovery

The extension adapter resolves elements by exact backend DOM node, frame, document and accessibility role/name. It waits for an attached, enabled, stable and unobstructed target. One bounded accessibility observation refresh can recover the same node; a replacement or ambiguous target requires a fresh snapshot and a new explicit selection. Accessible child frames use their own document identity. Restricted or unavailable frames are reported as unsupported.

Frame scope uses CDP's effective security origin. When Chrome reports the placeholder `://` for an inherited `about:blank` or `about:srcdoc`, a fixed query in that frame's isolated world establishes its actual origin. It never assumes a parent's origin: sandboxed opaque frames and frames swapped to inaccessible debugger targets are explicitly omitted from snapshots and cannot provide action UIDs. Such omitted child frames do not block supported main-document commands.

The backend remains the policy authority. Before a command, the trusted MCP adapter obtains hidden runtime context, applies current origin/data/action policy and binds exact parameters to an opaque single-use context token. The extension compares the current document, target, destination and parameter digest immediately before a side effect. The token is private adapter metadata and is absent from model schemas. Every inner dispatch in a batch rechecks the reviewed identities, destinations and material form data; only planned field value changes are accepted. Native form endpoints include submitter `formaction`/`formmethod` overrides, including the default submitter for Enter. Current permissions still decide ordinary actions; the extension does not introduce another approval authority.

Native submissions containing actual password/file controls or credential/payment autocomplete categories receive consequential-action handling even when the form uses GET. Ordinary GET search forms retain ordinary interaction permissions. This classification uses DOM control types and autocomplete tokens, not labels or model-provided claims.

Supported mutating tool results include `structuredContent.action_outcome`, also serialized as a separate MCP text block for compatible clients:

- `executed`: input was dispatched; no requested application-level condition was verified.
- `verified`: a fixed read-only observation established the requested condition.
- `failed` with `action_executed: true`: input was dispatched but the requested postcondition was not observed. This is not permission to repeat the input.
- `uncertain`: a response, connection or observation was lost after dispatch, or a batch stopped after a material context change. Reconcile the current page before continuing.

`expected_effect` accepts URL change/equality, element appearance/disappearance, value equality, dialog opening/closing and observable download start. Its optional timeout is bounded to ten seconds. Verifiers do not execute caller-supplied JavaScript. Field values, submitted content and raw error payloads are not included in verification diagnostics. A lost input reply can still resolve to `verified` when an independent read proves the exact requested effect; the action is never replayed to obtain that proof. The trusted parent adapter links the outcome to the existing Durable Journal operation, preserving uncertainty across recovery.

Visual fallback requires a fresh accessibility snapshot and a current viewport screenshot binding. Bindings contain actual image dimensions, CSS viewport dimensions, device scale, document identity and capture freshness. Coordinates are **viewport CSS pixels**, not image pixels. Scroll, resize, DPI, navigation or DOM/content changes invalidate the binding; it expires after thirty seconds and supports one click. The current point must hit an attached visible enabled DOM target. The same action policy and final context checks apply. Full-page/element screenshots and inaccessible frames cannot be used for coordinate dispatch. Coordinate-only actions without a verifiable DOM hit target stop instead of bypassing review.

Freshness observers run in a dedicated CDP isolated world. Document identity is derived from the CDP frame, loader, isolated execution context and connection epoch, so ordinary HTTP pages do not need secure-context crypto APIs and page scripts cannot edit the observer's state. Recovery never retries submitted inputs automatically. A reconnect invalidates old node/screenshot evidence; previously confirmed outcomes remain in the Journal.

Fixed DOM facts, inspection, focused-element resolution, visual hit testing and postcondition reads also use per-frame isolated DOM wrappers. Hardcoded functions running on main-world receivers would still execute page-defined getters, so backend nodes are resolved with the isolated execution-context ID. Native form prototype getters additionally prevent named child controls such as `name=action`, `method` or `elements` from replacing the actual submission facts. Click facts resolve the native control through text/label/ancestor targets. Arbitrary `evaluate_script` stays in the main page world and cannot execute caller code inside the trusted inspection realm. The real Chrome workflow includes hostile main-world form/button getters and named-property collisions, proving they cannot downgrade native POST classification or substitute its endpoint.

## Boundaries

Origin checks control subsequent agent commands and observable destinations. They do not contain every network request initiated by an arbitrary page or the user's existing Chrome profile. Arbitrary scripts and application event handlers can have opaque effects. Browser permissions, explicit review and trusted capability configuration govern those cases; labels and page text are not proof of authority. Upload file selection can trigger page handlers, so it receives external-effect handling; it does not prove a network upload completed. File-path revalidation narrows but cannot eliminate the race before Chrome independently opens a selected path. Cross-process/restricted frames requiring a separate debugger target are unsupported where the relay cannot inspect them reliably. A drag requires both exact targets to be actionable in the same viewport.

## Verification evidence

The main real-browser fixture launches Chrome/Chromium headlessly with a disposable profile and a local HTTP page. It exercises exact duplicate-name targeting, replaced nodes, actual same-origin iframe interaction, field-value verification, SPA navigation, an unmet business condition, actual screenshot dimensions and stale/one-use bindings, dialogs, strict context binding, multi-field form changes, and Enter-triggered native POST navigation with a submitter endpoint override. The mocked bridge suites additionally inject reply loss, disconnect/reconnect and destination changes during a batch, and exercise the real MCP server handler's public/private argument validation. These tests do not attach to the developer's profile or use their cookies.
